# MemScape simulation publication

The user requested a browser simulation linked from the product page on
2026-10-28. This publishes the existing fictional, session-only MemScape web UI,
not an account-backed journal. The hero CTA links to `/demo/`; the notice says
fictional memories, edits reset on reload, no sync. Existing native screenshots,
TestFlight links and product analytics are preserved. The demo page carries the
same Plausible tag as the product page, so visits appear as `/demo/` in the
`mem.scapedeck.com` dashboard; the `/demo/*` policy allows that origin for
`script-src` and `connect-src` and nothing else.

The snapshot is generated by `scripts/export-demo.py` in the separate private
`memscape-web` repository from a committed Git archive and locked offline
wasm-pack build. `demo-manifest.json` records the exact source, toolchain and
hashes. The JavaScript glue, WASM, snippet module tree and notices are included.
Only eight canonical synthetic photos are served under the app's existing
root-relative photo URLs. No standalone journal JSON, Rust source or private
fixtures are copied. Generated JavaScript and its required source snippets are
runtime assets. These committed artifacts are deployment inputs; this repository does
not contain their application build source.

## Verify and publish

```sh
python3 scripts/test-product-page.py
python3 scripts/test-demo-snapshot.py
python3 scripts/stage-site.py
wrangler whoami
wrangler deploy --dry-run
wrangler deployments list
wrangler deploy
```

Use the already installed Wrangler; do not install dependencies automatically.
The existing `wrangler.jsonc` targets `memscape-site`, account
`36aee5e0bd1fc4183ff378e9ba6eb59c`, domain `mem.scapedeck.com`, `_site` assets.
No route, account, DNS or infrastructure changes are part of this publication.
The stager requires tracked manifest entries with matching hashes and rejects
extra files, unsafe paths and symlinks. `_site` and local tracker files stay
ignored. Source and public candidates require independent review; browser QA
checks the actual staged UI, including native screen captures.

Before this publication, production was version
`79563a72-62d8-4632-945f-9d4bfee11e6b` (2026-10-29 01:51:56 UTC).
If live verification fails, use `wrangler rollback` targeting that exact version
and verify restored bytes. Record subsequent version IDs alongside the source
evidence in `memscape-web/docs/evidence/product-demo/`. Cloudflare deployment is
manual. The legacy GitHub Pages workflow is also manual (`workflow_dispatch`),
does not run on push, and is not used here; its older staging steps do not
include the demo. Use the validated stager and Cloudflare route above.

After publishing, verify product HTML and every manifest file by HTTPS and
SHA-256, then exercise the product link, five destinations, photos and editing
followed by reload. Preserve the resulting receipts. A later snapshot update
needs refreshed provenance, tests and review; it is not an app feature release.
